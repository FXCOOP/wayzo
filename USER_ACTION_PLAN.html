[Future] Integrate Main App with Supabase

Currently, the dashboard uses Supabase, but the main app still uses SQLite. This step outlines how to migrate the full app to Supabase.

📚 Technical Overview:

Current Architecture:

  • Main app (index.backend.html) → SQLite database
  • Dashboard (dashboard.html) → Supabase database
  • These are separate systems right now

To fully integrate, you need to:

Option A: Require authentication before generating plans

1. Add Supabase auth to main app (index.backend.html)
2. User must sign in before filling trip form
3. After payment, save plan using POST /api/user/plan (sends email)
4. User can view saved plan in dashboard

Option B: Anonymous plans with optional account linking

1. Allow users to generate plans without signing in (as now)
2. After payment, offer "Create account to save this plan"
3. If user creates account, migrate plan to Supabase
4. Otherwise, plan stays in SQLite (temporary)

Option C: Dual storage (current approach)

1. Keep main app using SQLite for anonymous users
2. Dashboard uses Supabase for authenticated users
3. Manually create plans in dashboard after payment
4. Migrate fully to Option A or B later

For now, Option C is active by default. The infrastructure is ready whenever you want to migrate.

🔧 Troubleshooting

Problem: Dashboard still shows fake data (Paris, Tokyo, Bali)

Solution: Clear your browser cache and hard reload (Ctrl+Shift+R). The Supabase credentials have been updated in the latest deployment. If the issue persists, check the browser console (F12) for errors.

Problem: Can't receive magic link email

Solution: Check your spam folder. If still not receiving, verify your email in Supabase dashboard → Authentication → Settings. Make sure email confirmation is enabled and the email provider is configured.

Problem: Dashboard shows "No plans yet" but I created plans before

Explanation: The old plans are in SQLite (local database on Fly.io). The new dashboard connects to Supabase (cloud database). These are separate systems. Old plans are not migrated automatically. You can manually copy data from SQLite to Supabase if needed.

Problem: Emails not sending from hello@wayzo.online

Solution: Complete Step 3 (Resend domain verification). Until the domain is verified, emails will send from Resend's default domain and may go to spam.
