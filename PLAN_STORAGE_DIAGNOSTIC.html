🔎 Step-by-Step Diagnostic

Step 1: Verify You're Signed In

  1. Open your main app at wayzo-staging.onrender.com
  2. Look at the top-right corner - do you see your email address or profile?
  3. If not signed in, click "Sign In" and complete authentication
  4. Open browser console (F12 or Right-click → Inspect → Console tab)
  5. Type this command and press Enter:
// Check if user is signed in if (window.supabaseClient) { window.supabaseClient.auth.getSession().then(({data}) => { if (data.session) { console.log('✅ SIGNED IN as:', data.session.user.email); console.log('User ID:', data.session.user.id); } else { console.log('❌ NOT SIGNED IN'); } }); } else { console.log('❌ Supabase not initialized'); }

Expected Result: Should show "✅ SIGNED IN as: your@email.com"

If it shows "❌ NOT SIGNED IN": Sign in first before generating plans!

Step 2: Generate a Plan While Signed In

  1. Make sure you're signed in (verified in Step 1)
  2. Fill out the trip planning form:
    • Destination: e.g., "Tokyo, Japan"
    • Start Date: Any future date
    • End Date: A few days later
    • Budget, travelers, etc.
  3. Click "Generate My Plan"
  4. Keep the browser console open (F12)
  5. Watch for these log messages:
📝 Creating plan for user your@email.com ✅ Plan [some-id] created for user your@email.com

What to look for:

  • Check console for "Creating plan for user" message
  • Check console for "Plan [id] created" message
  • Check console for any error messages (red text)
  • Note the Plan ID if shown

Step 3: Check if Plan Was Saved to Database

  1. Go to Supabase Dashboard
  2. Sign in to your Supabase account
  3. Select your project: wayzo-prod
  4. Click "Table Editor" in the left sidebar
  5. Select the "plans" table
  6. Look for recently created entries

What to check:

  • Are there any rows in the "plans" table?
  • Do you see your test plan with your user_id?
  • Check the "created_at" timestamp - is it recent?
  • Check if "html" column has content (not NULL)
  • Check if "destination" matches what you entered

✅ If you see your plan in Supabase:

Great! The plan is being saved. The issue is with displaying plans. Continue to Step 4.

❌ If you DON'T see your plan in Supabase:

The plan is not being saved. The issue is with saving plans. See "Common Issues" section below.

Step 4: Check Backend API Connection

  1. Open browser console (F12)
  2. Go to the Network tab
  3. Generate a new plan while watching the Network tab
  4. Look for a request to /api/user/plan (POST method)
  5. Click on the request to see details

What to check:

  • Status Code: Should be 200 OK
  • Request Headers: Should include "Authorization: Bearer [token]"
  • Request Payload: Should include your form data (destination, dates, etc.)
  • Response: Should include {"ok": true, "id": "...", "url": "..."}
// Good response example: { "ok": true, "id": "abc123-def456-ghi789", "url": "https://wayzo.online/backoffice.html#plan=abc123-def456-ghi789" }

❌ Common Error Responses:

  • 401 Unauthorized: Not signed in or token expired
  • 500 Internal Server Error: Backend or database error
  • 503 Service Unavailable: Supabase not configured on backend

Step 5: Check Backoffice Page for Plans

  1. Navigate to: https://wayzo-staging.onrender.com/backoffice.html
  2. Make sure you're signed in (if not, sign in with magic link)
  3. Open browser console (F12)
  4. Watch for these console messages:
Auth state changed: SIGNED_IN Loading your plans... 📋 Listed X plans for user your@email.com

What to check:

  • Page shows "Loading your plans..." initially
  • After loading, shows your plans OR "No plans yet" message
  • Console shows "Listed X plans" message
  • Network tab shows /api/user/plans request with 200 OK status

Step 6: Manual API Test

Test the API directly from browser console:

// Run this in browser console on backoffice.html page async function testAPI() { try { const session = await supabase.auth.getSession(); const token = session.data.session?.access_token; if (!token) { console.error('❌ No auth token - not signed in'); return; } console.log('✅ Got auth token:', token.substring(0, 20) + '...'); // Test fetching plans const response = await fetch('/api/user/plans', { headers: { 'Authorization': `Bearer ${token}` } }); console.log('📡 Response status:', response.status); const data = await response.json(); console.log('📋 Plans returned:', data); if (data.length === 0) { console.warn('⚠️ No plans found in database'); } else { console.log('✅ Found', data.length, 'plan(s)'); data.forEach(plan => { console.log(' - Plan:', plan.id, '|', plan.destination, '|', plan.created_at); }); } } catch (error) { console.error('❌ API test failed:', error); } } testAPI();

Copy and paste this entire code block into your browser console on the backoffice.html page, then press Enter.

⚠️ Common Issues & Solutions

Issue 1: Plans Not Saving at All

Symptoms: No plans appear in Supabase database

Possible Causes:

  • User not signed in when generating plan
  • Backend environment variables not set (SUPABASE_URL, SUPABASE_SERVICE_KEY)
  • Supabase service key has wrong permissions
  • Network error between backend and Supabase

Solutions:

  1. Verify you're signed in before generating plans (Step 1)
  2. Check backend logs on Render.com for errors
  3. Verify environment variables on Render.com:
    • Go to Render Dashboard → Your Service → Environment
    • Check SUPABASE_URL is set to: https://khrxfjekfzcvyjlzryyz.supabase.co
    • Check SUPABASE_SERVICE_KEY is set (should be a long JWT token)
  4. Test backend health: https://wayzo-staging.onrender.com/health

Issue 2: Plans Saved But Not Displaying

Symptoms: Plans exist in Supabase but backoffice.html shows "No plans yet"

Possible Causes:

  • User ID mismatch (plans saved under different user ID)
  • Frontend auth token not being sent correctly
  • Backend filtering plans by wrong user ID
  • CORS or authentication middleware blocking requests

Solutions:

  1. Check Supabase "plans" table - verify user_id column matches your auth user ID
  2. Run the manual API test (Step 6) and check console output
  3. In Supabase Dashboard:
    • Go to Authentication → Users
    • Find your email and copy the User ID
    • Go to Table Editor → plans table
    • Filter where user_id = [your-user-id]
    • If no results, the plans are being saved to wrong user ID
  4. Check browser console on backoffice.html for any JavaScript errors

Issue 3: Authentication Token Expired

Symptoms: 401 Unauthorized errors in Network tab

Solutions:

  1. Sign out completely and sign back in
  2. Clear browser cookies and localStorage
  3. Request a new magic link
// Run in console to clear auth and reload localStorage.clear(); sessionStorage.clear(); window.location.reload();

Issue 4: Wrong Supabase Credentials

Symptoms: 503 errors or "Supabase admin not configured" errors

Solutions:

  1. Check backend environment variables on Render.com
  2. Verify Supabase project settings:
    • Go to Supabase Dashboard → Project Settings → API
    • Copy the correct URL and service role key
    • Update environment variables on Render.com
    • Restart your backend service
