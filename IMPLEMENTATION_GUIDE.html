🎯 System Overview

Wayzo is an AI-powered trip planning application. After this implementation, users will be able to:

  • 📝 Sign up/Sign in with email (magic link via Supabase Auth)
  • ✨ Generate personalized trip plans using AI (OpenAI)
  • 💾 Save plans to their account (persistent storage in Supabase)
  • 📧 Receive email notifications when plans are ready (Resend)
  • 📱 View all saved plans in a personal dashboard (backoffice)
  • 📄 Download plans as PDF (Puppeteer + Supabase Storage)
🗄️ Supabase
PostgreSQL database + Authentication + Storage for user plans and PDFs
Auth Database Storage
✈️ Fly.io
Hosting platform running Express backend 24/7 with global CDN
Docker Node.js Always-On
📧 Resend
Modern email API for sending transactional emails (plan notifications)
Email Analytics

🏗️ System Architecture

Data Flow Diagram

1️⃣ User Opens Wayzo.fly.dev
User visits the main application → Frontend loads from Fly.io CDN
2️⃣ User Clicks "Generate Plan"
Frontend checks authentication status via Supabase client
🔐 Auth Check
If NOT logged in: Redirect to /backoffice.html → Show sign-in form → Send magic link via Supabase Auth
If logged in: Proceed to step 3
3️⃣ Submit Form Data
POST /api/plan with Authorization: Bearer {JWT_TOKEN}
Body: { destination, dates, travelers, budget, style }
🤖 Backend Processing
1. Validate JWT token (requireUser middleware)
2. Generate AI itinerary (OpenAI API)
3. Save to Supabase database (plans table)
4. Send email notification (Resend)
5. Return plan ID
4️⃣ Redirect to Backoffice
User redirected to /backoffice.html#plan={ID} to view the generated plan
✅ Plan Ready
User sees full itinerary + Download PDF button + Email notification sent

🔌 API Endpoints

All endpoints require Authorization: Bearer {JWT_TOKEN} header (except OPTIONS)

POST /api/plan
Create new plan for authenticated user
Body: { params: {...}, planJson: {...}, planHtml: "...", meta: {...} }
Returns: { ok: true, id: "uuid" }
GET /api/plans
List all plans for authenticated user
Returns: [{ id, title, destination, start_date, end_date, created_at, pdf_path, ... }]
GET /api/plan/:id
Get single plan by ID (owner only)
Returns: { id, user_id, title, content, html, params, ... }
GET /api/plan/:id/pdf
Get signed PDF URL (60 seconds expiry)
Returns: { url: "https://supabase.co/storage/v1/object/sign/..." }

🗄️ Database Schema

Plans Table

Column Type Description
id UUID Primary key (auto-generated)
user_id UUID Foreign key to auth.users (Supabase Auth)
title TEXT Plan title (e.g., "Trip to Paris")
destination TEXT Main destination
start_date DATE Trip start date
end_date DATE Trip end date
budget_low NUMERIC Minimum budget
budget_high NUMERIC Maximum budget
travelers INTEGER Number of travelers
style TEXT Trip style (budget, luxury, etc.)
params JSONB Original form parameters
content JSONB Structured plan JSON
html TEXT Rendered HTML of the plan
pdf_path TEXT Path to PDF in Supabase Storage
created_at TIMESTAMPTZ Creation timestamp
updated_at TIMESTAMPTZ Last update timestamp

Row Level Security (RLS) Policies

  • 🔒 SELECT: Users can only view their own plans (auth.uid() = user_id)
  • 🔒 INSERT: Users can only create plans for themselves
  • 🔒 UPDATE: Users can only update their own plans
  • 🔒 DELETE: Users can only delete their own plans
🛡️
Security: RLS ensures data isolation. Even if frontend is compromised, users can't access other users' data.

Storage Bucket: plans

PDF files stored at: plans/{user_id}/{plan_id}.pdf

-- Storage policy: Users can upload PDFs for their own plans CREATE POLICY "Users can upload own plan PDFs" ON storage.objects FOR INSERT WITH CHECK ( bucket_id = 'plans' AND (storage.foldername(name))[1] = auth.uid()::text );

Troubleshooting

Problem Solution
401 Unauthorized Check Authorization header includes valid JWT token
Insert failed Verify SUPABASE_SERVICE_ROLE_KEY is set correctly
Email not sent Check RESEND_API_KEY is set + verify domain in Resend dashboard
Plans not showing Open browser console → Check for API errors → Verify token
Magic link not working Check redirect URL in Supabase Auth settings
